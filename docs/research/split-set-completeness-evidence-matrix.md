# Split-set completeness evidence matrix

## How to read this matrix

The synthetic files contain only short ASCII payloads. The experiment harness assigned fixture ground truth (the hypothetical expected part count) separately from the observed directory entries. The resolver cannot see fixture labels. The positive pairs are decisive: each complete and incomplete scenario has exactly the same observed member names, types, lengths, and SHA-256 values. The harness also modeled an equal concatenation marker in both cases; that marker value was **assumed equal and was not set or tested on the host filesystem**.

Unless a row says “executed,” its result is source-based analysis or a proposed acceptance test, not a runtime test of NSCB. No Split layout was run through the production resolver because it intentionally fails closed.

## Interpretation

1. **Observations that establish terminal completeness:** none of the directory observations in P1–P3 does. A qualified, authenticated expected endpoint or count could do so only after its format and trust rules are proven. The XCI signed end-address field is a candidate, not a qualified result.
2. **Observations that establish structural consistency:** ordered names, no visible gaps, expected file types, accepted size bounds, valid container headers, and declared spans inside the observed bytes. These facts can reject malformed candidates but cannot reveal a missing terminal member.
3. **Observations that establish byte integrity:** a digest comparison can show the observed bytes match an independently trusted expected digest. A digest computed from the observed prefix and stored beside it is not independent completeness evidence.
4. **Observations that establish source stability:** the same-size mutation case shows path and size metadata are insufficient. Open handles reduce path retargeting risk but do not prevent in-place writes; a future design must state how it detects or prevents such changes.

## Experiment limits

The executed filesystem experiments used disposable files under a temporary directory and were removed by the harness. They measured common host filesystem names, hard-link identity, symlink identity, and path/size/hash changes. A separate disposable in-memory virtual-reader prototype exercised only the boundary cases described above. The experiments did not set Nintendo’s `ConcatenationFile` attribute, emulate transfer between operating systems, use copyrighted content, construct an authenticated XCI header, exercise real segment handles or NSCB parsers through the virtual reader, or call the NSCB resolver. No production Split behavior was changed.
