# Negotiate device capabilities without managing Switch-side software

NSCB treats compatible Switch-side responder software as a user-owned prerequisite rather than something NSCB installs, updates, bundles, or manages. Each connection derives a typed device capability set and planning rejects unsupported device operations before execution instead of assuming behavior from a product/version label. A lost connection terminalizes the active operation with a specific interruption result; host sources remain untouched, host temporary artifacts are cleaned when safe, and device-side state is reported as unknown unless the protocol can positively prove completion or rollback. Retrying creates a fresh planned attempt rather than resuming partial v1 state.
