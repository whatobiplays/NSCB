# Use plan-first in-process jobs

Every mutating NSCB operation is resolved into an immutable Operation Plan before execution, and user-requested work runs as an in-process Job that emits structured progress and results. NSCB does not require a daemon; v1 interrupted work never resumes automatically or from partial execution state. Process loss terminalizes the prior run as Interrupted, and an explicit retry creates a new Job with a freshly resolved plan linked to the prior run. Running work keeps its resolved execution context even if configuration changes; cancellation is cooperative with managed-process termination as a fallback, and automation never prompts for missing decisions or output conflicts.
