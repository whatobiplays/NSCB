# Use plan-first in-process jobs

Every mutating NSCB operation is resolved into an immutable, self-contained Operation Plan before execution. The plan carries all decisions, relevant configuration, selected providers, prerequisites, inputs, outputs, and conflict policy needed to execute without any later user input or prompting. Execution revalidates those preconditions immediately before mutation and fails with a typed stale-plan/precondition-changed result rather than silently rewriting the plan when reality differs.

User-requested work runs as an in-process Job that emits structured progress and results. The serialized `--plan`/JSON representation is an inspection artifact with no compatibility or replay guarantee and is not accepted as executable input. NSCB does not require a daemon; v1 interrupted work never resumes automatically or from partial execution state. Process loss terminalizes the prior run as Interrupted, and an explicit retry creates a new Job with a freshly resolved plan linked to the prior run. Running work keeps its resolved execution context even if configuration changes; cancellation is cooperative with managed-process termination as a fallback, and execution never prompts for missing decisions or output conflicts.
