# Harden untrusted-content and helper trust boundaries

NSCB treats content files and helper outputs as untrusted inputs. Extraction is confined to its resolved destination root, rejects traversal and special-object materialization, and creates only regular files/directories in v1; parsers use checked arithmetic, container-derived bounds, and explicit sanity ceilings rather than trusting declared sizes. Inspection requires an available valid key source rather than degrading into a partial no-key mode. Verification is strict for the requested scope: every applicable check must actually run and pass for verification to succeed; a missing key generation or other required prerequisite is a typed prerequisite failure rather than partial verification success, while non-applicable checks remain distinguishable from failures.

When a qualified helper needs keys, NSCB may pass the configured `prod.keys` path rather than copying key material into command arguments; raw key values remain excluded from logs, events, history, and diagnostics. Helpers run by exact qualified path with a controlled working directory and sanitized environment, local transformation contracts do not rely on network access, restoration claims require exact validated reconstruction, content-changing patches are always explicit in the Operation Plan, and outputs that fail NSCB postcondition validation are never published as successful artifacts.
