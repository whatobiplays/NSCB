# Treat external metadata as advisory enrichment

NSCB preserves read-only title metadata and update/DLC discovery behind NSCB-owned catalog contracts rather than binding application semantics to a legacy NUTDB/TitleDB schema or endpoint. v1 ships one qualified built-in TitleDB-compatible catalog provider, while supported catalog adapters may accept configured mirrors only for schemas NSCB understands; arbitrary scrapers or untyped JSON mappings are not part of the model. Catalog snapshots are validated as complete candidate snapshots, cached with source/version/timestamp provenance, and atomically promoted so a failed refresh never destroys the previous known-good snapshot.

Metadata enrichment may improve presentation and report update/DLC availability, but it does not silently change transformation bytes, verification truth, patch decisions, or deterministic naming; database export uses normalized stable JSON, JSONL, and CSV schemas. Local and connected-device inventories may be compared against the current catalog snapshot to report current/newer/missing/unknown related content without downloading it. v1 does not restore cloud-file providers or device autoupdate workflows.

Catalog intro/description text may be machine-translated to English through a narrow qualified translation-provider contract. v1 ships one integration against a documented supported translation API using user-provided credentials; it does not reproduce legacy unofficial `googletrans` endpoint behavior. Translation is lazy and cacheable by source text/snapshot, target language, and translator identity/version; only the text and minimum language parameters may leave NSCB. Translation is attempted automatically when the provider is configured and available, but translation credentials/service availability are never required for core metadata use. Translation failure or provider absence is non-fatal enrichment degradation: the original-language text remains usable, a lightweight translation-unavailable status may be presented, and translation can never fail a UI surface or Job. For v1 standalone use, translation API credentials may be stored directly in `config.toml`; raw credential values remain excluded from Job history, events, logs, diagnostics, and machine output. Embedded hosts supply translation credentials through host configuration/capabilities.

Standalone NSCB has an explicit offline policy that disables every NSCB-initiated network action, including release checks, catalog refresh, translation, and managed-helper download. Previously validated local helpers/catalog snapshots/cached enrichment remain usable; operations or planning that require unavailable network-derived prerequisites fail clearly rather than bypassing offline policy.
