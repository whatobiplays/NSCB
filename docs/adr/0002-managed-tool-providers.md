# Compose qualified external tools behind managed providers

NSCB may delegate specialized format, cryptographic, compression, or device mechanics to mature external executables instead of reimplementing every capability. Those tools are hidden behind NSCB-owned typed capability contracts, pinned to exact qualified versions, and validated as part of development and release qualification. Planning may provision the exact helper artifacts required by the immutable release manifest, and a valid Operation Plan is not returned until every required provider is installed, digest-verified, and ready; if policy or offline mode forbids required provisioning, planning fails with a typed prerequisite result.

Qualified installations are immutable artifacts installed atomically into a host-selected cache. Runtime discovery of arbitrary tools, user-supplied provider substitutions, silent provider replacement, and in-place helper upgrades are unsupported; development/tests may use explicitly non-production injection seams. Helpers are launched directly by exact executable path with typed argument vectors, never through a shell merely for invocation. Helpers eligible for automatic provisioning cannot require interactive license/EULA acceptance during normal installation; licenses/notices are surfaced through NSCB tool/license information, and any future provider requiring explicit acceptance must have that decision resolved before automation rather than prompting mid-plan. Standalone NSCB may validate, prefetch, repair, and bounded-clean old unused helper artifacts, but never removes current-manifest artifacts in use; embedded hosts explicitly own network and retention policy for their provided cache.
