# Ship CLI/TUI plus Argus support in v1

NSCB v1 ships the Rust core/embedding facade, CLI, interactive TUI, and supported Argus integration path; the dedicated NSCB Flutter application is a v2 deliverable. Every human-facing v1 operation exposed through the normal CLI is reachable through the TUI, including local content operations, device operations, Jobs/history, tool/provider maintenance, metadata/catalog workflows, and configuration; machine-specific presentation modes such as JSON/JSONL remain CLI/API concerns. The NSCB release candidate must be qualified by an Argus-owned integration against the exact candidate/release while both projects retain independent release versions and schedules. v1 distribution is through one signed/checksummed portable GitHub Release archive per supported target rather than package-manager channels or crates.io, and each archive contains the `nscb` executable, shell completions, generated manual/reference, notices/licenses, release metadata, and redistribution-compatible native libraries needed by NSCB where practical. External system setup is reserved for genuinely system-owned prerequisites such as drivers, permissions, or udev rules.

The release archive being portable does not make standalone mutable state portable: normal config, SQLite state, provider/cache data, diagnostics, and temporary application data live in platform-standard per-user locations rather than beside the executable. v1 does not provide a portable-state mode or automatically switch state location based on executable-directory writability.
