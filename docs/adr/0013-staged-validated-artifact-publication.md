# Stage and validate artifacts before publication

Mutating NSCB operations never modify source files in place and never destroy an existing destination before a replacement is complete. Standalone NSCB uses a deterministic, user-visible default output root for both single-item and batch work when the caller does not specify another destination, following the legacy product's dedicated output-folder model rather than scattering generated artifacts beside source files. Final artifacts are built on the destination filesystem where practical, validated against operation-specific postconditions, and only then atomically promoted or replaced; helper exit success alone is insufficient. Coupled multi-artifact outputs such as split sets are staged and validated as one publication unit and, where practical, promoted through an atomic parent-directory replacement rather than exposing completed parts incrementally. Independent batch items remain independently publishable.

Planning rejects duplicate resolved batch inputs, revalidates input identity and destination/workspace safety immediately before mutation, and execution detects source changes before publication so changed inputs cannot silently produce an accepted output. Atomic publication itself is a short non-interruptible critical section: if cancellation arrives after promotion has begun, NSCB completes that promotion to a known filesystem state, preserves the successfully published item, and prevents subsequent work.

When an explicitly requested transformation has nothing to change, NSCB returns a typed No changes required outcome and does not create a replacement artifact unless the operation itself requires a copy/repack. When an existing destination can be positively proven identical to the intended artifact, NSCB returns Already up to date rather than rewriting it; otherwise normal conflict policy applies. Generated artifacts receive ordinary safe destination-platform permissions and filesystem timestamps, without copying unrelated source metadata such as extended attributes, alternate streams, quarantine state, or timestamps unless an operation's data model explicitly requires it.
