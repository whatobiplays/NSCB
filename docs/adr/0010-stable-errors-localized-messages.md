# Separate stable error semantics from host-owned localized presentation

NSCB exposes stable typed error categories/codes and structured context across its CLI, Flutter bridge, and Rust embedding facade, while human-facing text is localized presentation owned by the active host. The CLI/TUI uses NSCB translation resources, the dedicated Flutter app uses its Flutter localization layer, and Argus maps NSCB semantics into Argus localization; no implementation string is displayed directly, and user-visible messages never expose code references, raw helper output, command lines, stack traces, or parser internals. Diagnostics may retain sanitized technical detail through the host-controlled diagnostics path. Standalone NSCB provides an explicit `diagnostics export` that creates a sanitized support bundle containing version/platform/provider information, relevant diagnostics, stable error codes, and sanitized plan/result context while excluding keys, API credentials, content payloads, and secret-bearing raw helper output; the export warns that paths and device metadata may still be private. v1 has no automatic telemetry or remote crash reporting, including opt-in crash upload.

v1 ships English only, but every user-facing surface is localization-resource backed so adding a language requires lightweight resource/UI wiring rather than production-domain or application-logic changes.
